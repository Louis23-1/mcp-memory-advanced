【架构铁律 — 必须逐条遵守，违反任一条即视为错误】

1. 核心纯函数化
   所有业务规则（信用检查、客户上限、仪表盘筛选、多语言翻译、激活验证等）
   必须写成纯函数。纯函数签名中通过参数传递差异（如 planLimits、langConfig），
   严禁在函数体内硬编码任何套餐名、语言代码或环境变量。

2. 矛盾维度正交拆解
   找出系统中独立变化的方向（例如：激活验证方式、套餐能力、云同步协议、
   输出语言），为每个方向定义独立接口（或配置对象），再通过组合/依赖注入组装，
   绝不在业务代码中使用 if(plan==='platinum') 或 switch(lang) 分支。

3. 开闭原则：新增功能 = 新增组件/配置，0 修改旧代码
   任何新需求（新套餐、新语言、新支付方式、新同步协议）只能通过新增文件/类/
   配置条目来实现。不允许修改已有函数内部逻辑。如果发现必须修改旧代码，
   说明抽象有问题，先重构再添加。

4. 策略/装饰器模式消除分支
   多态行为用策略工厂、装饰器包装，例如：
   - 激活验证：LocalVerifier / WorkerVerifier 实现同一接口
   - 云同步重试：withRetry(syncPush) 装饰器
   - 报表导出：createExportStrategy(plan) 根据配置返回函数
   工厂函数内部允许依据配置值分派，但不得依据套餐名称、语言代码等字面量。

5. 配置表驱除硬编码
   套餐差异、语言映射、支付渠道文案等全部放入查找表（PLAN_CONFIG、i18n字典）。
   业务代码只读取配置，不进行字面量比较。例如：PLAN_CONFIG[plan].maxCustomers，
   而非 plan==='bronze'?50:150。

6. 多语言全量切换（应用 UI + 系统框架，零死角）
   (a) 应用内 UI：
       - 任何面向用户的字符串不得以字面量形式出现在 HTML/JS/属性中。
       - 必须通过 t(key) 获取，动态文本用 t(key, ...args)。
       - 使用 data-i18n、data-i18n-placeholder 等属性标记静态文本，
         由统一脚本在语言变更时扫描刷新。
       - 第三方库文本配置需从 i18n 字典动态获取。
   (b) 系统框架级文本（必须随语言同步切换）：
       - document.title：每次语言变更时重新设置，值从翻译字典取。
       - meta description / keywords：内容从 i18n 获取并实时更新。
       - PWA Web App Manifest：
           · 根据当前语言动态设置 <link rel="manifest"> 的 href
             （如 manifest_fr.json、manifest_zh.json），
             每种语言预置对应的 manifest 文件。
           · 如果无法预置，至少在 Service Worker 激活时用当前语言更新
             manifest 的 name 字段（如支持）。
       - Service Worker 内的通知文本（更新提示、离线提示等）
         必须通过消息或全局状态获取翻译后的字符串，禁止硬编码。
       - 语言切换时，以上所有系统级文本必须和应用 UI 一起自动刷新，
         不允许“UI 是法语，标题还是英语”的情况。

7. 单真理源与数据流向
   - 核心数据模型（如订单、客户）唯一，任何功能只能读取和派生，不可修改其形状。
   - 全局状态（当前语言、当前套餐、激活状态）只有一处可写入口，其他所有组件只读。
   - 网络、存储、DOM 操作只能在外围适配层进行，核心纯函数绝不触碰副作用。

8. 错误处理统一范式
   所有异步操作返回 { success: boolean, data?: any, error?: string } 结构。
   禁止返回 null/undefined 表示错误，禁止抛出未捕获异常来控制业务流程。

9. 安全与密钥保护
   HMAC 密钥、ACTIVATION_SECRET 等敏感信息绝不出现在前端代码、日志、错误提示中。
   验证逻辑通过可替换的验证器接口隔离，内部实现可用本地或远程，业务层不感知。

10. 代码生成前自查
    输出任何代码前，先确保：
    - 没有使用套餐名称做条件判断
    - 没有硬编码字符串
    - 没有直接操作 IndexedDB/DOM/网络
    - 新增功能未修改已有函数签名
    - 系统框架文本（标题、manifest、SW 通知）已纳入语言切换体系
    若违反，重写。

11. 数值数组存 BLOB，不存 JSON 字符串
    向量嵌入（embedding）、坐标序列、信号采样等浮点数组，使用数据库原生
    二进制类型存储（SQLite BLOB、PostgreSQL BYTEA），配合
    struct.pack / np.ndarray.tobytes() 序列化。严禁将浮点数组转成
    JSON 字符串存入 TEXT 列。
    —— 原因：JSON 序列化的解析开销随数据量线性增长，BLOB 直接
    memcpy 到 numpy 数组，查询侧的自定义函数也无需反复 json.loads。

12. 外部接口层必须兜底异常
    任何对外暴露的函数（HTTP handler、MCP tool、CLI entry point）必须
    在最外层自行 try/except，捕获所有异常并返回结构化错误：
    { ok: false, error: "描述信息" }，绝不能把裸异常抛给调用方。
    这独立于第 8 条的业务层错误范式——第 8 条管内，本条管边界。
    例：MCP tool 的 call_tool 分发函数中，每个 case 内部应 try/except
    并返回 TextContent 格式的错误文本，而非让 mcp SDK 收到未处理异常。
